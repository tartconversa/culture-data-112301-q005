# 后续数据接入指南

应用只消费符合 `docs/资料契约.md` 的记录。本文说明新增/替换数据时的步骤、
必须维护的契约位置，以及常见错误的表现。

## 1. 接入新一批合成资料

1. 用与现有文件相同的 UTF-8 JSONL 编码替换或新增 `data/<table>.jsonl`，
   每行一条记录，主键在表内唯一；空值用 JSON `null`，已知空集合用 `[]`。
2. 更新 `data/catalog.json` 中对应表的：
   - `row_count`：新行数；
   - `sha256`：整个文件字节的 sha256（`sha256sum data/<table>.jsonl`）；
   - 新增字段时同步 `fields` 的 `type/nullable/description`；
   - 新增直接外键时同步 `references`（目标表名 + 目标键）。
3. 运行 `python3 tools/check_materials.py`，必须输出各表行数且无异常；
4. 运行 `python3 -I -m unittest discover -s tests -v`，全部通过后再使用应用。

不更新 catalog 会直接得到 `资料指纹不符` / `资料行数不符` 错误，这是预期
的防呆行为，不要绕过校验。

## 2. 各表接入要点

| 表 | 接入注意 |
| --- | --- |
| works | `parents` 只能引用已存在的作品；应用支持任意深度谱系，循环引用会导致展开异常，接入前需自检无环 |
| licenses | 地域为列表、用途只能是 `preview`/`release`；`guarantee_pool` 必须存在于 guarantees |
| releases | `works` 内作品必须存在；三日期允许 null，语义见资料契约；迟来的回执优先放 late_evidence 而不是改写旧行 |
| usage_logs | 同一真实使用的多份镜像必须共享 `origin_event` 且 stage/on/observed_units 一致；只有 coverage 允许不同，应用据此识别覆盖分歧 |
| statements | 修订产生新 id、更高 `revision` 的新行，不要原地改旧行 |
| guarantees | `reserved_minor` 只登记资料外既有有效承诺；应用自身报价占用写入 state，不回写此表 |
| terms | 新增条款必须显式填写 `allowed_with`；组合合法性为双向判定 |
| renewal_requests | 同客户互斥方案共享 `alternative_group`；`expires_on` 决定授权事件是否有效 |
| authorization_events | 只记录原始动作，不要在此表预判合同成立；`party` 必须与事件日适用权利人一致，否则确认无效 |
| late_evidence | `release_receipt` 的 value 是正式发行日；`ownership_ruling` 的 value 是新权利人 id，裁决自 `on` 生效，无溯及力 |

## 3. 追加声明（不改原始资料的推荐方式）

业务中反复到达的季度声明应放到 data/ 之外的独立目录，通过应用导入：

```sh
python3 -I tools/run_app.py import-statements /path/to/extra_statements.jsonl
```

文件记录字段与 statements 完全一致；导入动作进入 `state/ledger.jsonl`，
重复运行会因 id 冲突被拒绝。清空本地状态用 `reset`，原始资料不受影响。

## 4. 接入全新来源

新来源需要新表时：

1. 在 `catalog.json.tables` 注册表名、字段、指纹、行数；
2. 在 `app/store.py` 的 `MaterialStore` 增加对应的 `_build_*` 方法与属性；
3. 在 `app/models.py` 增加冻结数据类；
4. 若新来源参与证据判断，在 `app/evidence.py` 扩展效力解析而不是在 CLI
   层打补丁；
5. 为新规则在 `tests/` 增加最小夹具测试（参考 `tests/fixtures.py` 的内存
   仓库构造方式），不要依赖全量数据的偶然取值。

## 5. 金额与日期约定

- 所有金额字段为整数美分，应用内部不引入浮点金额；
- 日期为 `YYYY-MM-DD` 公历字符串，比较按字典序即时间序；带 Z 时间戳若未来
  引入，需先在 store 层归一化；
- 所有输出 JSON 均由 `app.models.to_dict` 或 dataclass `vars()` 产生，字段
  名稳定，可被下游系统直接依赖；新增字段只能追加，不要改名或改语义。

## 6. 排障速查

| 现象 | 原因与处理 |
| --- | --- |
| `DataIntegrityError: 资料指纹不符` | data 文件变更后未更新 catalog sha256 |
| 全部使用 `billable=false` | 先查 `rights[].reasons`：合成资料中客户许可地域与发行地域大面积错位是预设场景，不是程序错误 |
| 报价一直 pending | 查 `request <id>` 的 `blockers` 与 `history`，区分待客户接受、待权利人确认、担保不足、独占冲突 |
| 担保可用额度对不上 | guarantees.reserved_minor 是基线占用；报价占用在 `guarantees` 命令的 `quote_reserved_minor`，过期/撤回后释放 |
| 对账单位与声明差异大 | 日志按 origin_event 去重且 preview 不入对账；覆盖分歧事件在 disputes 中逐条可查 |
