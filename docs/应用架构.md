# 应用架构与业务规则

本文说明 `app/` 如何把 `data/` 中的合成记录转成可解释的许可消耗与续约方案。
资料字段口径以 `docs/资料契约.md` 为准，本文只描述计算规则与模块边界。

## 1. 模块划分

```
app/
  models.py               数据类与结果对象（金额统一为整数美分）
  store.py                资料读取 + 指纹/外键校验 + 本地状态账本
  lineage.py              衍生谱系、可达原作、归属裁决时点
  evidence.py             镜像去重、证据效力、权利覆盖、批次状态
  statements_reconcile.py 声明修订、季度对账
  pricing.py              条款组合合法性、计价、用量投影、权利人分配
  quoting.py              报价状态机、授权判定、独占与担保占用、互斥组
  amendments.py           声明修正/归属裁决/范围缩小的影响判断
  service.py              门面：装配上述模块，CLI 与测试共用
  cli.py                  命令行入口
tools/run_app.py          python -I 下的运行入口（显式注入仓库根目录）
```

依赖只用 Python 标准库；`requirements.txt` 固定的科学计算栈不是应用运行所
需，保留给后续分析型维护者。

## 2. 资料载入与本地状态

- `MaterialStore` 复用 `tools/check_materials.py` 的全部校验（sha256 指纹、
  行数、字段集合与类型、直接外键），任何不符都抛 `DataIntegrityError`，
  应用拒绝在损坏资料上计算。
- 原始资料只读。应用动作写入 `state/ledger.jsonl`（只追加），快照写入
  `state/snapshot.json`；重建 `Application` 时重放账本即可恢复报价与导入
  状态。`state/`、`outputs/` 已在 `.gitignore` 排除。
- 账本条目带 `domain`：`quote`（issue/expire/withdraw）、`statement_import`
  （追加声明文件路径）、`scope_narrowing`（发行范围缩小登记）。

## 3. 使用证据到许可消耗

### 3.1 镜像去重

`usage_logs` 的两行镜像共享 `origin_event`，载入时折叠为一个 `UsageEvent`，
保留全部镜像 id。镜像间 `coverage` 不一致时标记 `coverage_disputed`，同一
使用永远只核算一次。

### 3.2 证据效力（由强到弱）

| 级别 | 触发条件 | 计费含义 |
| --- | --- | --- |
| `release_receipt` | release 阶段且发行包有正式回执（含迟报补录） | 可计正常收入（仍须授权齐备、覆盖无争议） |
| `package_record` | package 阶段，或 release 阶段但回执缺失 | 缺少回执不等于没有使用；有授权即可计，冲突中注明迟报可能 |
| `preview_only` | preview 阶段 | 编辑预览不产生正式发行权，永不计收入 |
| `insufficient` | 保留级别（当前数据未产生） | 证据不足，挂起 |

迟报 `late_evidence/release_receipt` 在 `as_of` 之前到达即补全发行日与回执
到达日（R000 即此情形：原始记录无回执，LE1 于 2026-10-10 补录 2026-04-01
发行）。

### 3.3 billable 判定

一条去重事件计入正常收入必须**同时**满足：

1. 阶段为 package/release（preview 排除）；
2. 实际触及的每个作品（自身 + 全部可达原作）在该客户、地域、日期存在
   purpose=release 的有效许可；preview 用途许可不覆盖 release 使用；
3. 无其他客户的独占 release 许可冲突；
4. 镜像覆盖无分歧且 coverage=1.0（覆盖存疑保守计收，列入争议清单）。

不满足时 `billable=false` 且 `conflicts` 给出机器可读原因，未授权使用绝不
进入收入口径。

### 3.4 衍生谱系

`Lineage.effective_works(work)` 递归展开 `parents` 去重。衍生素材自身有许
可不代表原作可用：W8 的一次 release 使用同时要求 W8、W0、W1 的地域许可。

### 3.5 批次观察状态

- `complete`：`end_on` 非空且该批次全部事件覆盖完整无分歧；
- `observing`：存续未结束，或覆盖不足/有分歧。

观察批次不等于零用量，其单位单独累计，续约分析中与完整批次分开报告。

## 4. 归属裁决

`ownership_ruling` 自 `on` 起更换权利人：

- `Lineage.owner_on(work, date)` 取不晚于该日期的最后一次裁决，否则取
  `works.owner`；
- 裁决日之前的既有许可按当时权利人解释，不追溯改写；
- 跨越裁决日的许可：裁决日前继续有效，裁决日后的使用列入
  “需补授权或补偿”；
- 续约请求的授权事件要求 `party` 等于事件日适用权利人，旧权利人在裁决后
  的确认记 `owner_event_wrong_party`，不填补授权缺口；许可起日适用权利人
  与确认日权利人不同也会阻塞成立。

## 5. 声明与对账

- 同 `(customer, quarter, territory, work)` 只取最高 `revision`，被取代的
  声明 id 保留在 `superseded_statement_ids`；
- 追加导入的声明走 `StatementLedger.import_file`，身份 id 不可复用；
- 对账状态：`matched / overstated / understated / no_observation`。
  少报不直接判违约，可能是渠道迟报或日志覆盖下降；
- 声明修正只刷新未来投影与对账，已成立合同的历史收入不重写。

## 6. 续约计价

### 6.1 合法组合（`allowed_with` 双向满足）

- 单条款：`usage`、`capped`、`guarantee`
- 唯一多条款组合：`guarantee + usage`
- `capped` 不可与任何条款组合；不存在的拼法直接拒绝，不能挑各条款最低价
  拼报价。

### 6.2 计价公式（美分）

| 方案 | 按量部分 | 最低/封顶 | 总价 |
| --- | --- | --- | --- |
| usage | 40 × units | — | 按量部分 |
| capped（period） | 25 × units | 最低 80000，封顶 150000 | clamp(按量, 最低, 封顶) |
| guarantee（minimum） | 20 × units | 保底 100000 | max(按量, 保底) |
| guarantee+usage | 40 × units | 保底 100000 | max(按量, 保底)，保底抵扣同范围按量费，绝不重复累加 |

### 6.3 用量投影

按请求的客户/地域过滤事件，展开请求作品的可达原作，输出：观测单位、按
coverage 折算的上界、完整批次单位、观察批次单位、未授权单位、按作品明
细。观察批次占比高即代表回收不确定性，不能把单位下降直接解释为价格弹性
——`summary` 同时给出 `log_coverage_ratio`。

### 6.4 担保池与权利人分配

- 担保池只能覆盖其 `works/territories` 内的请求；容量 =
  `limit - reserved - 其他报价占用`；
- pending/formed 报价按方案的保底额预占，过期/撤回立即释放；报价评估自身
  时不计自己的占用；
- 权利人收入按其作品的历史单位占比分配，给出
  `low_minor/high_minor/guaranteed_minor` 区间；担保不可用时
  `uncovered_liability_minor` 标出无法被担保覆盖的责任。

## 7. 报价生命周期

```
draft ──issue──► pending ──条件齐备──► formed（生成 EL-<request> 有效许可）
                    ├──expire──► expired（释放担保预占）
                    └──withdraw──► withdrawn
```

成立条件（与客户接受、权利人确认的到达次序无关，按日期重放）：

1. 事件日不晚于 `expires_on`；过期后到达的授权不复活报价；
2. 客户已接受；
3. 范围内每个作品（含可达原作）都取得当时适用权利人的 `owner_confirm`；
4. 独占请求不与既有独占许可/其他 formed 报价冲突；
5. 含保底方案通过担保池作品、地域、容量校验；
6. 同一客户同一 `alternative_group` 至多一个 formed（互斥约束与独占无关，
   始终生效）。

formed 后的条件承诺不可被更优方案替换（重复签发报错）；`mutual-exclusion`
查询输出每组的 formed/pending 与一致性。

## 8. 修正影响（`amendments` 命令）

- `statement_revision`：列出被取代声明，声明未来口径只用最新修订，合同历
  史收入保留；
- `ownership_ruling`：列出受影响既有许可，区分裁决日前继续有效与裁决日后
  需补授权/补偿；
- `scope_narrowing`（`narrow-release` 登记）：同步到引擎的 `ResolvedRelease`，
  撤回日后的使用 `billable=false` 并带 `scope_narrowed_on_*` 冲突，被撤回
  作品移出该使用的 `effective_works`；受影响许可继续持有但缩小范围内不再
  产生新计费，超出剩余范围需新授权。重放账本时缩小登记会重新作用于引擎。

## 9. 常用命令

```sh
python3 -I tools/run_app.py consumption            # 全部 900 条去重使用的消耗解释
python3 -I tools/run_app.py disputes               # 仅争议/未授权/证据不足
python3 -I tools/run_app.py rights                 # 逐作品权利覆盖
python3 -I tools/run_app.py batches                # 完整/观察批次
python3 -I tools/run_app.py reconcile              # 声明对账
python3 -I tools/run_app.py import-statements f.jsonl
python3 -I tools/run_app.py summary                # 客户×地域用量与覆盖
python3 -I tools/run_app.py request Q0             # 方案比较+授权评估
python3 -I tools/run_app.py issue Q0 guarantee+usage --on 2026-11-01
python3 -I tools/run_app.py expire Q0 --on 2026-11-16
python3 -I tools/run_app.py narrow-release N1 R001 --on 2026-09-01 --drop-territory NA
python3 -I tools/run_app.py guarantees             # 担保池占用
python3 -I tools/run_app.py amendments             # 修正影响
python3 -I tools/run_app.py reset                  # 清空 state/
```

加 `--export` 会把结果同时写入 `outputs/<command>.json`。
